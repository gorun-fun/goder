> (ZCode / 其他 agent)。目标:按本文档完成系统性回归,产出结构化测试
> 报告。人肉测试同样适用。

## 1. 测试形态与入口矩阵

goder 是同一份前端跑多形态的应用。**测试优先级:test-serve(自动化主战场)
→ 桌面 App(平台差异专项)→ web/embed 形态(回归)**。

| 形态 | 入口 | 自动化方式 | 覆盖面 |
|---|---|---|---|
| **test-serve**(无头测试态) | `goder test-serve` | 浏览器自动化(playwright 等),**AI 主战场** | 除「原生窗口/webview 专属」外的全部桌面能力:终端面板、配置持久化、gh 托管、文件浏览、git 审查、设置全分区、聊天全流程、自动化操作员 |
| 桌面 App | 发布版 .app / .exe | 手动 + computer-use 类工具 | 窗口装饰/拖拽缩放、右栏**原生**浏览器面板、原生对话框(目录选择)、自动更新、托盘退出 |
| web 网关 | `goder-web-serve`(静态 + `/goder-api`) | 浏览器自动化 | 纯 web 行为:localStorage 持久化、agent API 代理路径、多用户网关 |
| 嵌入库 | `frontend/dist-embed/goder.js` 宿主页 | 浏览器自动化 | 嵌入方 API:registry 装配、换肤、事件总线、共享右栏面板 |

### 1.1 test-serve 形态说明(重要)

`goder test-serve [--port 7460]` 用同一份发布版二进制起一个无头实例
(不创建窗口,wails 事件循环、服务启动钩子、gh 冷启动全部照常),把完整
桌面 UI 经本地 HTTP 服务器暴露给浏览器:

```console
$ goder test-serve --port 7460
test-serve 就绪(仅 127.0.0.1,退出: Ctrl+C):
  打开:       http://goder.localhost:7460/?t=<随机令牌>
  直连形式:   http://127.0.0.1:7460/?t=<随机令牌>
  探活:       HEAD http://goder.localhost:7460/goder-host-probe → 204
  优雅退出:   POST http://goder.localhost:7460/test-serve/quit?t=<令牌>
```

- **必须用带 `?t=` 令牌的完整 URL 访问**(首次访问种 HttpOnly cookie,
  后续同源请求自动携带;无令牌一律 403)。Linux 上 `*.localhost` 不解析
  时用 127.0.0.1 直连形式,行为一致。
- 探活等待就绪:`HEAD /goder-host-probe` 返回 204 即可开始。
- 收尾用 quit 端点优雅退出(勿直接 kill -9,让 gh 子进程走正常回收)。
- **保真度差异**(相对桌面 App,详见 §5 平台差异矩阵):
  - 资产加载走本地 HTTP 服务器(与 Windows 生产态同一条路径;
    macOS/Linux 生产态走 wails 资产服务——差异仅在传输层);
  - 页面跑在系统浏览器引擎,而非各平台 WebView(WKWebView/WebView2);
  - **不可测**:原生 webview 浏览器面板(无宿主窗口,自动回退 iframe
    模式)、窗口控制/拖拽、原生目录选择对话框、自动更新的重启阶段。
- **数据与环境注意**:
  - test-serve 与桌面 App **共享**配置、项目索引与 gh server(托管实例
    幂等收养);goder-console 的启动期烙写会互相覆盖端口/令牌,
    **不要与桌面 App 同时运行**;
  - 测试机器需 `gh` 可执行文件(macOS .app 内已捆绑;裸二进制需在 PATH
    或已配置绝对路径,缺失时 macOS/Linux 会静默自动下载);
  - 模型配置沿用 `~/.grf/settings.json`(`GRF_HOME` 可重定位)。聊天类
    用例需要一个可用模型;纯 UI 用例不需要。

## 2. 测试方法约定

- **双轨断言原则(核心)**:每个功能用例 = **行为断言 + 视觉断言**。
  DOM 断言证明"功能发生了"(按钮点了、状态变了),截图证明"界面如预期
  呈现了"(禁用态真的灰了、流式真的逐段出现、布局没挤坏)。**只做 DOM
  断言的用例是不完整的** —— UI 表现与功能不一致(点了没反馈、状态变了
  但界面没跟上、样式挤压溢出)恰是 E2E 最该抓住的缺陷,DOM 断言天然
  盲区。多模态模型必须看截图判定,视觉验证点见 §2.1 与 §3.9。
- **断言方式**:优先 DOM 断言(AI/ARIA 树、可访问名、元素状态),必要时
  `evaluate` 读页面状态(如 xterm buffer、store 字段);视觉断言用截图
  (规范见 §2.1)。goder 前端为 Lit + shadow DOM:元素查找需穿透 shadow
  root(`el.shadowRoot.querySelector`),registry 驱动的面板在
  `goder-app-shell` 内。
- **终端面板输出断言**:`goder-terminal` 元素持有 `term` 实例,读
  `term.buffer.active.getLine(i).translateToString(true)` 比读 DOM 可靠。
- **每轮测试前**:重启 test-serve(新令牌、干净进程);需要数据隔离时
  用测试用户账户或先备份 `~/Library/Application Support/goder/`(macOS)
  与 `~/.grf/`。
- **严重级别**:P0 阻断(崩溃/白屏/数据丢失)、P1 功能失效、
  P2 功能可用但交互/显示异常(**视觉不一致默认归此级及以上**)、
  P3 体验瑕疵。
- **报告**:按 §8 模板输出;每个用例给 结论 + 证据(DOM 断言值 + 截图,
  两者都要)。测试日志见 test-serve 进程 stdout。
- **已知噪音**(非缺陷):设置页打开时审查面板对非 git 目录报
  `fatal: not a git repository`(右栏 git 审查轮询,预期行为);
  远程更新检查失败(无网络环境)。

### 2.1 视觉验证规范(多模态模型执行)

**截图纪律**:

- **动作前后各一张**:关键状态变更(发送、切会话、开面板、切主题)截
  "操作前 + 操作后"两张,证明变化发生且方向正确;只截结果图无法发现
  "根本没反应"。
- **全页 + 定点**:布局类用全页截图;局部缺陷(按钮态、卡片内部、溢出)
  加目标元素截图,定位到具体 DOM。
- **固定环境变量**:统一视口(默认 1280×720;响应式验证按 §3.9 矩阵
  变换)、统一主题与字号,只在专项用例中切换;截图时避免光标悬停等
  偶然状态(hover 态单独专项验证)。
- **流式/过渡态**:流式回复、终端输出等动态过程,在过程中截 1 张
  (证明逐段出现而非一次性出全文)、结束后截 1 张(证明终止态正确)。

**判定标准**(每张截图必须回答):

1. 布局完整:无重叠、无溢出裁切、无错位;各栏宽度比例合理。
2. 状态可见:加载中/禁用/激活/空态/错误态有明确的视觉区分。
3. 反馈即时:操作后的界面变化与功能断言同步(按钮态、列表项、指示器)。
4. 一致性:同一控件的视觉风格在会话/设置/弹层间一致;亮暗主题下均无
   不可读对比度问题。
5. 文案呈现:长文本换行正常、不截断关键信息、时间/版本号格式统一。

**基线比对(可选增强)**:设置页等稳定界面可存基线截图做像素级比对;
聊天区等动态内容不做像素比对,以"判定标准"问答代替。基线随版本更新
重建,避免跨引擎(§5.5)误报。

**边界说明**:test-serve 截图验证的是布局/状态/一致性逻辑,跑在系统
浏览器引擎;WKWebView/WebView2/WebKitGTK 的引擎级渲染差异(字体回退、
CSS 边角)仍按 §5.5 在各平台桌面 App 抽查。

## 3. 功能测试清单

> 以下用例默认在 test-serve 形态执行(桌面 App 专项见 §5,web/embed
> 专项见 §4)。标 ★ 的为冒烟必测项(§7)。
> **每个用例除文字描述的预期外,默认附带视觉验证**:用例中描述的界面
> 表现(高亮、面板出现、渲染)都必须以截图确认(§2.1 判定标准);
> 横切视觉状态(空/错/载/禁用/溢出/主题/视口)统一在 §3.9 专项覆盖。

### 3.1 启动与冷启动

- ★ **页面加载**:带令牌 URL 打开后 10s 内出现完整界面:左栏(会话/
  项目列表)、中部聊天区(消息输入框)、顶栏;无白屏、无报错浮层。
- ★ **gh 冷启动**:`/goder-api/token` 返回 `{"mode":"managed","running":true,...}`;
  顶栏模型选择器出现已配置模型;上下文占用指示有值。
- **无模型守卫**:模型未配置时(空 settings.json),加载后自动跳转
  设置→模型分区引导。
- **init 诊断**:正常路径下不出现 init 诊断标记(顶栏)。

### 3.2 左栏:项目与会话

- ★ **新建项目**:点「新建项目」→ 选择/输入目录 → 项目出现在列表,
  会话归属该项目;刷新页面后仍在(持久化)。
- **项目操作**:查看文件(左栏切换文件树)、新建会话(在该项目下建
  草稿)、删除项目(确认弹层 → 项目与其会话归档消失)。
- **文件树**(桌面能力):目录条目按「目录在前、名称升序、隐藏条目
  滤除」排列;点击文本文件在右栏开文件预览 tab(标题为文件名);
  图片文件预览为图片。**web 形态此入口隐藏**(无此能力,不显示报错)。
- ★ **会话列表与切换**:多会话并存;点击切换后聊天区、详情、事件台
  跟随;当前会话高亮。
- **会话草稿**:输入未发送的内容切走再切回,草稿保留;发送后草稿落定
  为会话首条消息。
- **未分组会话**:不属于任何项目的会话归入「未分组会话」组。
- **会话删除/重命名**:入口可用,操作后列表即时更新。

### 3.3 聊天面板(核心)

- ★ **发送与回复**:输入消息回车 → 用户消息上屏 → 模型流式回复逐段
  渲染 → 完成后状态恢复可发送;回复支持 markdown(标题/列表/代码块/
  行内代码/粗斜体)。
- ★ **中断**:流式回复中点停止 → 立即停止,已渲染内容保留。
- **重发/复制**:助手消息「复制」「编辑后重新发送」可用;编辑重发走
  草稿编辑路径。
- **工具卡**:模型调用工具时渲染工具卡(名称、参数、结果可折叠);
  终端类工具显示命令;浏览器类工具显示页面快照入口。
- **审批与 ask**:工具审批卡出现时 允许/拒绝 均生效;ask 卡输入回传。
- **附件**:「添加附件(图片)」选择图片 → 随消息发送,消息内渲染。
- **模型/推理档切换**:顶栏模型选择器切换模型;推理档(高/…)切换后
  下一条消息生效。
- **上下文占用**:指示条随会话长度变化;超出时提示。
- **完全访问开关**:切换后下一条消息的权限模式变化(工具面随之)。
- **`/` 指令**:输入框键入 `/` 弹出指令列表;选择后执行对应行为。

### 3.4 右栏面板

- **浏览器面板**(嵌入/通用):默认 iframe 模式可导航 URL、前进/后退/
  刷新;console 与网络捕获在 iframe 模式不可用属预期(仅原生模式支持,
  见 §5)。
- **审查面板**(桌面能力):在 git 项目下显示分支、ahead/behind、
  变更文件列表、行级 +/− 统计;点文件看 diff。非 git 目录显示空态而非
  报错卡死。
- ★ **终端面板**(桌面能力,test-serve 可测):打开底栏/右栏终端 →
  PTY 建立(shell 提示符出现)→ 输入 `echo OK` 回车 → 回显 `OK` →
  「新建终端」开第二个会话 → 关闭 tab/会话退出无残留进程。
- **文件预览 tab**(桌面能力,被动入口):从文件树/聊天工具卡打开;
  多文件各占一个 tab;标题为文件名;关闭 tab 干净。
- **右栏开合**:「右栏面板」按钮开合;tab 记忆跨会话切换保留。

### 3.5 设置分区(registry 装配,六个内置分区)

- ★ **外观**:主题(亮/暗/跟随系统)、强调色、字号切换即时生效;
  刷新后保持(localStorage 镜像)。
- ★ **模型**:供应商列表增删改;探测模型(GET /models)填充模型列表;
  默认模型选择;`~/.grf/settings.json` 写入正确(桌面态;web 态经
  agent API,密钥不下发明文)。
- **Harness**:托管模式 启动/停止/状态 gh server(状态含 addr/pid);
  远程模式填 URL/令牌后连接;gh 二进制路径、服务地址修改后重启生效。
- **插件**:列表显示内置插件(浏览器/电脑操作、界面控制 goder-console
  不可删);自动发现目录与显式列表模式语义正确;在线安装/删除。
- **MCP**:远程 MCP 条目增删改(url/token/超时);保存后 settings.json
  的 plugins 键结构正确。
- **技能**:列表(~/.grf/skills)、启用/禁用(SKILL.md ↔ .disabled)、
  新建/编辑/删除、从 URL 安装;内置技能 goder-auto 存在且不可删/编辑。
- **设置导航**:分区导航与分组(基础设置/智能体)正确;返回会话入口。

### 3.6 桌面托管与更新(test-serve 可测前者)

- **gh 生命周期**:设置→Harness 停止后 `/goder-api` 断连(聊天报连接
  错误而非卡死);启动后恢复;test-serve 重启后收养既有 gh 实例
  (pid 不变)。
- **更新检查**:设置/左栏更新入口触发检查 → 显示 goder 与 gh 两组件的
  当前/最新版本对比。无更新时明确提示。**更新的下载/重启阶段仅桌面
  App 专项测**(test-serve 无窗口,重启语义不适用)。

### 3.7 自动化操作员(桌面能力,test-serve 可测)

- **操作员类别**:左栏「自动化」类别仅桌面态显示;「添加操作员」在
  主目录建同名工作区目录。
- **操作员会话**:新建操作员会话 → 首条消息自动注入 system_prompt
  (含 goder-auto 技能全文)→ 对话正常。
- **任务沉淀**:会话中输出 `<goder-task>` 块 → 聊天区渲染任务卡 →
  保存进 `index.automation`(刷新后仍在;migrateIndex 不清空)。
- **执行入口**:状态弹层(status-pop)出现自动化任务入口 → 点击
  在该操作员下新建 run 变体会话。
- **技能沉淀**:run 会话成功跑通后输出 `<goder-skill>` 块 → 渲染技能
  保存卡 → 保存落 `~/.grf/skills/<名>/SKILL.md`(test-serve 可测;
  web 态卡片禁用保存)。

### 3.8 goder-console 智能体控制面(桌面能力)

> 用一个 gh 会话(模型侧)或直接 MCP 客户端调用 loopback 7450 端口验证。
> 设置页「界面控制」显示连接状态。

- `goder_terminal_*`:新建/输入/增量读缓冲,与手动终端行为一致。
- `goder_browser_*`:导航/快照 ref 机制/点击输入/console 与网络捕获/
  截图(快照合成事件无 isTrusted,依赖可信事件的页面行为差异属预期)。
- `goder_ui_*`:界面操作经 `goder:console-ui` 事件下发,shell 映射执行
  (如切会话/开面板);`goder_ui_state` 能读到界面状态 JSON。

### 3.9 视觉一致性专项(UI 表现 × 功能一致)

> 本组是横切专项:功能正确但呈现错误的缺陷都在这里抓。每个矩阵项
> = 截图 + §2.1 五条判定标准逐条回答。

**A. 状态可见性(每个状态都要有视觉区分)**

| 状态 | 触发方式 | 视觉验证点 |
|---|---|---|
| 加载中 | gh 冷启动期间、模型探测中、会话历史拉取中 | 有加载指示(spinner/骨架),不空白也不假装完成 |
| 流式中 | 模型回复期间 | 逐段出现(截过程图)、停止按钮可点、输入框禁用或提示中 |
| 禁用 | 无模型时发送、不可写 settings 的保存按钮 | 视觉灰化 + cursor 变化,点击无响应 |
| 空态 | 无会话/无项目/无插件/无技能/终端未开 | 有引导文案与入口,不是裸空白;各分区空态风格一致 |
| 错误态 | 断 gh 后发消息、非法路径打开文件 | 错误卡片/提示样式统一,可关闭或可重试,不阻塞其他区域 |
| 激活/选中 | 当前会话、当前设置分区、当前右栏 tab | 高亮清晰且唯一,切换后旧高亮消失 |

**B. 主题 × 视口矩阵**(每格一张全页截图)

| | 亮色 | 暗色 |
|---|---|---|
| 1280×720(默认) | ☐ | ☐ |
| 1920×1080(宽) | ☐ | ☐ |
| 880×620(桌面最小宽度) | ☐ | ☐ |

- 桌面最小宽度下:左栏可收起(「收起侧栏」按钮)、右栏/底栏面板与
  聊天区不挤压重叠。
- 暗色主题专项:无纯白刺眼块、无暗底暗字不可读;强调色在两主题下均可辨。
- 字号档位:每档截一张,排版不溢出不截断(中文长词、代码块横向滚动)。

**C. 内容溢出与长内容**

- 超长会话标题/项目名:截断省略号或换行,不撑破列表与顶栏。
- 超长代码块:块内横向滚动,不撑破消息卡;行号对齐。
- 超长无空格串(URL/base64):可换行或滚动,不横向溢出容器。
- 大量会话(≥30 条):列表滚动流畅,新建会话后视口滚到该项。
- 聊天流式期间自动跟随滚动,用户上滚后停止跟随(手动回到底部入口出现)。

**D. 交互即时反馈(表现与功能同步)**

- 发送瞬间:输入框清空、用户消息上屏、按钮进入加载态 —— 三者同一帧级
  发生(前后截图对比)。
- 切换会话:聊天区内容与标题即刻替换,无残影、无闪烁白屏。
- 打开右栏/底栏面板:面板滑入或出现动画完整,布局重排无跳动。
- 复制成功:有反馈(toast/图标变化),不是无声操作。
- 删除确认弹层:遮罩、焦点、Esc/点遮罩关闭行为与视觉一致。

**E. 嵌入形态视觉专项**(配合 §4.2)

- 宿主页无样式泄漏:宿主 CSS 不影响面板、面板样式不泄漏到宿主
  (双向隔离各验一例)。
- 换肤:改 `--goder-*` 变量前后截图对比,所有面板跟随变化。

## 4. web 与嵌入形态专项

### 4.1 web 网关(goder-web-serve)

- `./build.sh web` 起服务后:登录(按身份模式)、项目索引存
  **localStorage**(刷新保留;与桌面文件持久化互不干扰)。
- `/goder-api` 代理链路:会话/消息/模型配置(agent API 路径,密钥明文
  不下发,`hasKey` 语义正确)。
- **多用户隔离**(header/sso 模式):两用户各自独立 gh 进程
  (GODER_DATA/users/<uid>/),数据互不可见;端口池懒启动、空闲回收。
- 桌面专属入口全部隐藏且无报错(终端/审查/文件预览/自动化类别/更新)。

### 4.2 嵌入库

- 宿主页加载 `frontend/dist-embed/goder.js`(ESM、零外部依赖):
  页面正常渲染、shadow DOM 样式自隔离(宿主 CSS 不影响面板)。
- **换肤**:仅经 `--goder-*` CSS 变量生效。
- **registry API**:hide/show/add/remove 四区条目均生效;自定义导航/
  右栏/底栏/设置分区可注册;`shared` 右栏面板跨会话共享。
- **事件总线**:`uiEvents`(壳层页面变更可接管/放行)、`newProject`
  (嵌入方接管新建项目)、`setProjectPath`(对账校正项目路径)。
- **默认提示词**:项目 defaults 的 `system_prompt` 与 `default_skill`
  经 `grf:session` 透传注入。
- **测试装具**:`dist-embed/test-harness.html`(fake 模式)打开即测:
  12 个场景按钮、10 个扩展点开关、`window.goderKit` 快照/脚本/请求;
  `goder:round-completed`/`goder:conn-state` 事件可等待断言。接入方视角
  的完整指导见 `docs/integration-testing.md`。
- 细节与职责边界表见 `docs/embedding.md` 第 5 节。

## 5. 平台差异矩阵(差异化测试)

> 单平台测试不能保证跨平台一致;一致性的根基是仓库不变量(AGENTS.md),
> 本矩阵是**各平台必须单独验证的差异面**。三平台 = macOS / Windows /
> Linux。

| # | 差异点 | macOS | Windows | Linux | 测试方式 |
|---|---|---|---|---|---|
| 1 | **资产加载路径** | wails 资产服务(`wails:` scheme,支持流式) | 本地 HTTP 服务器(`goder.localhost`,绕过 WebView2 响应缓冲) | 同 macOS(WebKitGTK) | 桌面 App:发消息观察**流式逐段渲染**(非回合结束一次性出全文);test-serve 形态三平台同走本地 HTTP 路径 |
| 2 | **右栏浏览器面板** | 自建 WKWebView 子视图;eval 走 callAsyncJavaScript 回调 | WebView2 窗口重父级子窗;eval 走 fetch 回报 `/goder-eval-report` | 不支持 → iframe 回退 | 桌面 App:导航、console 捕获、网络捕获、截图各过一遍;eval 信封格式两边对拍(改格式必须两边同步,见 `internal/browser/eval.go` 头注释) |
| 3 | **窗口装饰** | 隐藏标题栏留红绿灯 | 无边框 + 前端自绘 `.winctl` | 无边框 + 自绘 | 桌面 App:最小化/最大化/关闭、拖拽、双击缩放、边缘缩放 |
| 4 | **终端 PTY** | forkpty | ConPTY | forkpty | test-serve 三平台各跑 §3.4 终端用例(建 PTY/回显/退出/多会话) |
| 5 | **WebView 引擎** | WKWebView(JavaScriptCore) | WebView2(V8/Blink) | WebKitGTK | 引擎级回归:聊天 SSE 流式、markdown 渲染、shadow DOM 布局;发现引擎差异缺陷标 P2+ |

Windows 下 `*.localhost` 内建解析;Linux 若不解析用 127.0.0.1 直连形式。
三平台跑同一套浏览器自动化流程即为差异化矩阵的自动化部分。

## 6. 双形态不变量(结构性检查)

- **嵌入产物零外部依赖**:`frontend/dist-embed/goder.js` 不含
  `@wailsio/runtime` import、无外部 CDN 引用。
- **桌面专属模块不进嵌入产物**:terminal/review/file-view 不出现在
  dist-embed。
- **registry 装配**:内置面板均经 registry 注册;chat-panel/app-shell
  无硬编码面板类型(代码走查)。
- **DTO 同步**:`internal/desktop` 服务 DTO 与 `frontend/src/host/bridge.ts`
  接口字段一致(代码走查)。
- **版本比较三处同语义**(发版相关):`compareVersion` / `version.sh`
  的 `ver_max` / CI 捆绑逻辑,用矩阵用例(内测/公测/候选/正式/postN/
  跨基线)验证。
